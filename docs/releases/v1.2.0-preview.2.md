# v1.2.0-preview.2

Prerelease for acceptance testing. Live PVE and installed-service acceptance is **still pending** and required before a stable release.

**Breaking for unauthenticated remote setups:** startup now fails when `Server:Host` is not loopback and `Server:Password` is blank. This includes the Docker image's default `0.0.0.0` bind. Set `Server:Password`, or opt in with `Server:AllowUnauthenticatedRemote=true`.

- Fail closed when the MCP endpoint would listen remotely without a password. `/healthz` reports the authentication mode (#1).
- Advertise `update_qemu_config`/`update_lxc_config` `fields` as a constrained object schema, which fixes clients whose schema converters rejected the `true` schema (#4).
- Add `/access` tools for users, privilege-separated API tokens, roles and ACLs (#2):
  - Listing is read-only.
  - Writes need `ReadOnly=false` and `AllowAccessManagement=true`. Removals also need `AllowDestroy=true`.
  - Token secrets are returned once and never logged.
- Add ordered multi-endpoint support with `BaseUrls` (#3). A single `BaseUrl` still works.
  - Reads fail over on network, TLS and authentication failures, with bounded backoff.
  - Mutations are never resent.
  - Tool results report the serving endpoint in `_meta`.
  - `get_api_endpoints` shows and probes endpoint health.
- Add opt-in `VerifyCertificateHostname` (default false). It requires certificates trusted through `CaCertificatePath` to match the endpoint host.

New settings default to the previous behaviour. Read [endpoint failover](https://github.com/Wixely/ProxmoxMCPSharp/blob/v1.2.0-preview.2/docs/endpoint-failover.md) and [access management](https://github.com/Wixely/ProxmoxMCPSharp/blob/v1.2.0-preview.2/docs/access-management.md) before enabling them.

Local verification:

- 242 synthetic HTTP/MCP tests passed on Windows and Linux CI. They include real loopback TLS tests for hostname verification.
- Failure classification was checked against real sockets.

Failover against a live multi-node PVE cluster and access management against a live PVE realm have **not** been tested.

**Acceptance still to do (operator, before stable release):**

- Everything listed for [v1.2.0-preview.1](https://github.com/Wixely/ProxmoxMCPSharp/blob/v1.2.0-preview.2/docs/releases/v1.2.0-preview.1.md).
- Fail over between two live cluster nodes: take the preferred node offline, then bring it back. Confirm that a mutation during the outage is not replayed.
- Provision and remove a service identity on a disposable realm, then confirm the token's effective permissions.

Record results in the [acceptance checklist](https://github.com/Wixely/ProxmoxMCPSharp/blob/v1.2.0-preview.2/docs/verification.md). A successful GitHub build does not complete acceptance.
