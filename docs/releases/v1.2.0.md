# v1.2.0

Stable release of the v1.2.0 preview line. The code is the same as [v1.2.0-preview.2](https://github.com/Wixely/ProxmoxMCPSharp/releases/tag/v1.2.0-preview.2), plus release documentation.

**Breaking for unauthenticated remote setups:** startup now fails when `Server:Host` is not loopback and `Server:Password` is blank. This includes the Docker image's default `0.0.0.0` bind. Set `Server:Password`, or opt in with `Server:AllowUnauthenticatedRemote=true`.

## Since v1.1.7

- **Diagnostics (read-only):**
  - Paged task history and logs.
  - SMART, ZFS pool health and managed directories.
  - Storage diagnostics and bounded backup coverage.
- **Guest management (opt-in):**
  - QEMU/LXC disk growth and disk/mount-point management.
  - Resource and structured configuration updates.
  - LXC clone/migration.
  - Stronger source/destination authorization.
- **Access management (opt-in):** `/access` tools for users, privilege-separated API tokens, roles and ACLs. Writes need `AllowAccessManagement=true`, and token secrets are returned once.
- **Endpoint failover:**
  - Ordered `BaseUrls`; a single `BaseUrl` still works.
  - Reads fail over with bounded backoff.
  - Mutations are never resent.
  - `get_api_endpoints` reports endpoint health.
- **TLS:** opt-in `VerifyCertificateHostname` for certificates trusted through `CaCertificatePath`.
- **Security:** the server refuses to listen remotely without a password, and `/healthz` reports the authentication mode.

Defaults stay safe:

- `ReadOnly=true`.
- `AllowDestroy`, `AllowAccessManagement`, `AllowDiskResize`, `AllowDiskManagement` and `AllowResourceChanges` are all false.

Read [guest management](https://github.com/Wixely/ProxmoxMCPSharp/blob/v1.2.0/docs/guest-management.md), [access management](https://github.com/Wixely/ProxmoxMCPSharp/blob/v1.2.0/docs/access-management.md) and [endpoint failover](https://github.com/Wixely/ProxmoxMCPSharp/blob/v1.2.0/docs/endpoint-failover.md) before enabling them.

## Verification

- 242 synthetic HTTP/MCP tests passed on Windows and Linux CI.
- Endpoint failure classification and certificate hostname checks were tested over real loopback sockets and TLS.

**This release was promoted without live Proxmox acceptance.** That was the owner's decision. Live PVE behaviour of the management, access-management and failover features has not been verified, and neither have installed-service (Windows Service/systemd) or ARM64 runtime behaviour. Try these features on non-production guests and clusters first. The open checklist and the promotion decision are in [verification.md](https://github.com/Wixely/ProxmoxMCPSharp/blob/v1.2.0/docs/verification.md).
